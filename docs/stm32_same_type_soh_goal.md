# 同类型新电池 SOH 曲线预测与 STM32 部署方案

设计日期：2026-10-04。新训练和软件部署准备已完成，详见 `docs/stm32_soh_training_result_20261004.md`。硬件检测未发现开发板；按当前Goal中明确允许的“硬件不可用时完成软件产物并列出待板端验证事项”分支交付，不声称已经完成实机部署。

## Goal

在 MIT、XJTU 内按电池类型及已知工况组织数据，用整块电池隔离的训练、验证和测试，训练只接收已观测电压、电流、可选温度及历史统计的小型模型。对同类型、未参与训练的新电池输出未来 SOH 曲线；MIT、XJTU 分别达到逐电芯等权平均 MAPE <= 6%，并在指定 STM32 上完成量化模型推理验证。

## 任务边界

- MIT 与 XJTU 分别训练、分别验收；按现有物理类型登记和已知工况分层，不按最终寿命或未来曲线分类。XJTU 注册队列不代表所有同容量电池都可接入。
- 先复用现有 N=100 源循环起点，预测之后实际有真值的全部未来曲线。N=20/50 作为后续早期预测扩展，不增加首轮范围。
- 部署输入是类型/工况、截至起点的信号特征、可见循环计数和请求的未来循环；不用容量、真实当前/未来 SOH、真实总寿命作为输入。
- 新电池先积累对应的观测前缀和初始参考曲线，再预测。训练和实机使用同样的采样窗口、单位、参考和特征计算方式。
- 未来预测以保持训练覆盖的工况为前提；瞬时 V/I 单点不作为完整寿命曲线预测的充分输入。
- NASA 保留作小样本补充，不作为首轮两类部署验收的必达对象；RUL、跨类型迁移及新的大型模型搜索不纳入首轮任务。

## 实施顺序

1. 复核现有合格 PC 基线，冻结 MIT/XJTU 电芯划分、预测起点、未来评价范围和质量清单。复用现有数据与结果，不从零搜索。
2. 固定一套约 20–40 维输入：标准窗口 V/I 采样或统计、相对初始曲线变化、截至起点的变化趋势、循环计数与已知工况；温度仅在训练和部署都可获得时使用。
3. 每类训练一个数值 MLP，例如特征及未来循环 -> 32 -> 16 -> 1，采用 ReLU。逐未来循环输出 SOH，组成预测曲线；训练按电芯平衡，验证集选轮数和少量候选结构。用固定预测网格查看平滑程度和末段偏差，必要时加入轻量平滑约束。
4. 若小网络直接监督未达标，使用训练电池拟合的现有树模型或合格教师辅助蒸馏，同时保留真实 SOH 监督。教师、蒸馏样本和量化校准不使用测试电池。SMETimes/LLM 可作为 PC 教师候选；最终固件只依赖数值特征与小网络。
5. 在训练侧数据上校准 INT8，导出支持的模型格式和固定标准化常量。使用 ST 工具生成 C 推理代码，将相同的流式特征提取和模型接口接入固件。
6. 用未见测试电池的信号回放比较 Python、量化模型、C 推理与实机预测，并测量资源。最终再用一块符合类型/工况的新实物电池演示，实物精度需要后续容量诊断真值验证。

## 数据质量规则

规则先于训练/测试固定：核实重复电池、单位错误、损坏记录、非有限值、时间和通道错位、明确中断片段。可修复则修复，否则排除问题记录并保存原因。输入不足标记不可用并报告覆盖。真实衰减快、寿命短或预测误差大不等同于坏数据；不按 MAPE>6% 删除测试电池。

## 验收

- 每块测试电池先计算未来真值点上的 MAPE，再在 MIT/XJTU 各自内等权平均；两类分别 <=6%，不能用混合平均抵消某类失败。报告逐电芯误差、MAPE<=6%比例、可用/总电芯数量、末段结果与真实/预测曲线。
- 最终量化/板端输出也按同一协议达到 <=6%；不能只用桌面教师成绩验收小模型。
- 初始工程预算：每类网络 <=50,000 参数，模型权重及预处理常量 <=128 KiB，模型推理工作 RAM <=32 KiB。固件代码、采集缓冲和历史状态另外计入整机 Flash/RAM，必须给出实测总占用。
- 初始时延目标：指定 STM32 上单次模型查询 <=100 ms；完整曲线的耗时另报。具体板型和可用资源未确定前，该项是设计预算，不是已验证性能。
- 交付冻结划分/质量清单、训练配置、Python与量化模型、C源码、信号回放样例、逐芯预测与指标、资源测量和板端演示记录。
