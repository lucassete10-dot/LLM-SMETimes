# SMETimes 电池健康预测项目概况（供 ChatGPT 学习指导）

> 本概况根据本地仓库代码、配置和截至 2026-10-13 的实验报告整理。它介绍的是这个仓库的实际内容，不等于原始 SMETimes 论文的完整复现说明。后续教学如果涉及具体实现，请让我提供对应源码，不要仅凭文件名猜测。

## 1. 项目在做什么

项目目录为 `D:\LLM\SMETimes-main-WINDOWS`。它最初是一个在 Windows 上运行的 SMETimes 时间序列预测项目，后来扩展成了以锂离子电池健康状态预测为主的研究仓库。

当前主线研究问题是：**能否根据一颗电池前 100 个实际源循环中可见的电压、电流、温度、时间信号及事先已知工况，使用预训练语言模型与 SMETimes 风格的融合机制，预测这颗电池后续的 SOH 退化曲线？**

这里的语言模型作为数值预测网络的一部分使用，最终输出的是 SOH 数值和曲线。项目同时保存了传统机器学习、小型神经网络、RUL 预测和 STM32 部署等历史分支。

## 2. 需要先理解的概念

- **电芯与循环**：一颗电芯有多次充放电循环。不同电芯的寿命、工况和退化速度不同。
- **SOH（健康状态）**：本项目容量标签通常以容量除以参考容量构造；1.0 表示参考容量水平，0.8 表示参考容量的 80%。参考容量规则需要看对应数据版本，不能统一假定为额定容量。
- **RUL（剩余使用寿命）**：距离定义的寿命终点还有多少循环。历史分支研究过这个任务；最新五数据集主线重点是未来 SOH 曲线。
- **预测起点 origin**：当前主线固定在源循环 100。历史输入只能来自该时刻及以前，未来循环号可作为查询位置。
- **MAPE 与 pp**：MAPE 是相对误差百分比；SOH 绝对误差乘 100 后的单位为百分点（pp）。SOH 相差 0.01 对应 1 pp，不能直接当成 MAPE 1%。
- **电芯划分**：训练、验证和测试应按电芯隔离，避免同一颗电芯的信息进入多个角色而造成过于乐观的评价。

## 3. 仓库里有三条需要区分的路线

### A. 原始通用时间序列预测框架

以 ETTh1 等时间序列数据为例：预处理生成时间文本嵌入，训练时把数值序列分块，通过线性层或 MLP 投影到 LLM 隐藏空间，与时间嵌入融合，经过冻结语言模型、专家模块及解码器输出预测。

主要入口是 `preprocess.py`、`run.py`、`data_provider/`、`exp/exp_long_term_forecasting.py` 和 `models/SMETimes_Llama.py`。另有 GPT-2、OPT 版本。

### B. 电池数据处理与历史模型实验

包括 NASA、CALCE、MIT、XJTU 等数据适配、容量标签和寿命终点定义、短窗口信号特征、SOH/RUL 模型、未来轨迹模型、跨工况评估及多种基线。大量根目录 `adapt_*`、`train_*`、`evaluate_*`、`audit_*` 文件属于这些实验。

这些历史分支的输入、目标、划分和指标不一定与最新主线相同，成绩不能直接混在一起比较。

### C. 当前 LLM + SMETimes 电池曲线主线

最新完成的是五数据集 v3 实验。它使用真实预训练 Llama-3.2-1B-Instruct，将电池历史信号变成数字 token 和统计文本卡，学习历史表示，再解码未来 SOH 曲线。它是针对电池回归任务的改造，不能理解为直接调用原始模型文件就能完成全部电池实验。

## 4. 当前主线的输入、计算和输出

```text
各数据集原始文件
    ↓ 适配、清洗、循环与标签对齐
统一电芯数据 + 固定 TRAIN / VAL / TEST 名单
    ↓ 仅截取源循环 ≤100 的可见信号
训练集拟合的缺失值处理、标准化、缺失掩码
    ↓
数字历史分块 → 数字投影 ─────────┐
历史 V/I/T 统计 → 文本卡 → LLM 编码 ─┤
                                  ↓
                         数字/文本融合
                                  ↓
                         冻结 Llama 主干
                                  ↓
                         SMETimes 风格专家模块
                                  ↓
                         LLM 历史 token 表示
                                  ↓
未来循环查询 + 已知工况 → 起点/退化速率/局部修正解码
                                  ↓
                         后续循环的 SOH 曲线
```

主干权重通常冻结，训练数字投影、融合门、低秩专家和预测头等适配参数。代码也支持仅数字通道使用的 LoRA 候选，但最新 v3 的 LoRA 候选没有被最终采用。

曲线解码包含根据历史表示预测起点、积分退化速率和有限局部修正等机制。它不要求真实容量曲线处处严格单调，可以容纳受约束的小幅恢复。所有预测分支都依赖 LLM 历史表示。

**推理输入不包含真实容量、真实 SOH、未来信号、真实寿命或真实终点。** 容量/SOH 用于训练监督和评估；不能把真实 SOH 拿来平移预测曲线，也不能针对待测电芯用未来标签拟合参数。缺失通道需明确表示。

## 5. 数据集与评价范围

最新主线按数据集分别训练，并不等于训练了一个统一跨数据集模型。

| 数据集 | 全源电芯数 | 正式 TEST 覆盖 | 评价特点 |
|---|---:|---:|---|
| MIT | 134 | 134 | 五折，每折三个种子 |
| XJTU | 55 | 55 | 五折，每折三个种子，工况差异值得关注 |
| HUST | 77 | 16 | 固定留出，三个种子，其余电芯参与 TRAIN/VAL |
| UConn_ISU_ILCC | 64 | 11 | 固定留出，三个种子，SOH 标签为稀疏 RPT 观测 |
| Zhu2022_NCA | 55 | 55 | 五折，每折三个种子 |

TRAIN 用于拟合预处理和模型；VAL 用于选择配置、检查点和停止时机；锁定配置后才评价 TEST。已经查看过的 TEST 被项目明确称为“开发留出”，不再作为独立盲测宣传。

评价不仅看平均 MAPE，还看逐电芯逐种子通过率、起点误差、后期误差、终点误差和阶段下降量误差。稀疏数据仅评价真实观测点，不能靠插值证明逐循环曲线准确。

## 6. 当前进展与局限

根据 `docs/LLM_SMETimes_v3_five_dataset_results_20261013.md` 和完成审计，v3 已完成 51/51 个正式训练槽位，固定三个种子，共有 66 次实际新拟合（含筛选与确认）。最终各数据集都保留 R0 配置；共享查询读出和数字 LoRA 的同预算候选没有满足接受条件。

| 数据集 | TEST 平均 MAPE | 三个种子均 MAPE≤3% 的电芯 |
|---|---:|---:|
| MIT | 2.186% | 102/134 |
| XJTU | 2.508% | 39/55 |
| HUST | 2.626% | 8/16 |
| UConn_ISU_ILCC | 2.171% | 7/11 |
| Zhu2022_NCA | 2.096% | 38/55 |

这些是仓库报告中的开发留出结果，本概况没有重新训练复现。**执行方案完成，但精度目标只部分达到**：平均误差较小并不表示每颗电芯或曲线各阶段都准确。仍存在起点偏差、过早下降、末段加速缺失和尾段漂移。UConn 的连续曲线形态证据不足。三种子均值曲线不能替代逐种子验收，图中种子标准差也不是置信区间。

## 7. 技术栈与环境

- Windows、PowerShell、Python；仓库运行说明使用 Python 3.12 和本地 `.venv`。
- PyTorch：神经网络、自动微分、GPU 训练。
- Transformers：加载本地 Llama 等模型及 tokenizer。
- NumPy、Pandas、SciPy、h5py、openpyxl、PyArrow：数据处理与文件读取。
- scikit-learn：预处理和传统模型；Matplotlib：结果图。
- JSON/YAML：配置与元数据；NPZ：电芯数组和预测；模型权重及状态文件：检查点、恢复与重放。
- 运行说明针对 RTX 50 系显卡记录了 CUDA 12.8 的 PyTorch 配置；实际环境应按本机检查结果确认。

## 9. 建议的代码阅读顺序

1. 先建立完整任务认识：输入是什么、预测什么、训练和测试怎样划分。
2. 学电池标签与数据结构：`battery_data_contract.py`，再看当前主线数据准备脚本和一颗处理后电芯的字段。
3. 学张量和数据预处理：`research_sequences.py`，理解样本、历史长度、特征维度、掩码和标准化。
4. 学原始模型思想：`models/SMETimes_Llama.py`，理解分块、投影、融合、冻结主干和专家模块。
5. 学当前电池模型：`research_llm.py` → `llm_query_rate.py` → `llm_local_recovery.py`。
6. 学训练与验证：先看较简单的 MVP 入口，再看 `train_llm_curve_v3.py` 与 `llm_curve_quality_v3.py`。
7. 学实验可信度：按电芯隔离、未来信息隔离、消融、同预算比较、随机种子、检查点重载和结果重算。
8. 最后再研究跨工况泛化、RUL、传统模型对照和 STM32 部署。
